# Interviewing for context

Run the conversation that produces `profile/honest-context.md` — what the candidate wants
next, what they will not accept, what their situation actually is, and what they are
genuinely weak at. Prose, no schema, dated, with a numbered list of dealbreakers at the
end.

`references/honest-context-interview.md` is the whole procedure: why a conversation and not
a form, the technique that gets a real answer rather than a tidy one, the nine areas to
cover, and how to write the file. Read it before you start. This page is only the framing.

## Why this file is worth fifteen minutes

> Without `honest-context.md`, every skill downstream of it degrades into a generic
> résumé-to-posting tool: no idea what the candidate wants, what they will walk away from,
> or which parts of their CV are thin. It is the one file nobody else can write, because it
> is made of things the candidate has not said out loud yet.

`assessing-job-fit` checks it before it does anything. `tailoring-applications`,
`writing-a-linkedin-profile`, `roasting-a-resume` and `aligning-career-targets` all read it
and all say so when it is missing. Fifteen minutes of the first pass — what they want, the
hard constraints, what they will not claim, the dealbreakers — is enough to make all of
them work properly. Say that, and stop there if their attention is going.

## Read first

| File | Required | If missing |
|---|---|---|
| `references/honest-context-interview.md` | yes | The procedure. Do not run the interview from memory. |
| `profile/honest-context.md` | no | This is what you are creating. If it exists, read all of it — you are revising, not starting over. |
| `profile/resume.json` | no | Read it if present, to ground the conversation in real roles and dates. The interview works from what the candidate says, not from the file. |
| `profile/tone.md` | no | If they mention drafting in a second language, that answer goes here, not in honest-context — move it and tell them. |

## Output

`profile/honest-context.md`, and there is no heading contract for it on purpose. The file
is named after what the candidate said — someone whose whole search turns on a visa gets a
section called that, near the top — not after the nine areas in the procedure. Prose, in
their words, dated, uncertainty marked inline.

The one fixed element: **the dealbreakers are a numbered list at the end.**
`assessing-job-fit` reads that list before it assesses anything, and a dealbreaker buried
in a paragraph gets missed.

Stop when the candidate tires. Mark what is unfinished rather than filling it with
something plausible. Half a page of true things beats two pages where a third is invented.

## Tone

The interviewer's, not the form's. Ask about the last time rather than the general case,
never accept an adjective without the occasion behind it, follow the hedge, and read it
back in their words before you write it down. Blunt is fine; leading is not.

Do not write down what you deliberately did not ask about. A note listing the private
topics you avoided has just filed them somewhere new.

## If the environment has more tools

Nothing here requires any of them. This is a conversation and one file. A filesystem MCP
server is fine if that is how the workspace is reached. Do not reach for web search — there
is nothing on the internet about this person that belongs in this file.

## After writing it

- Tell the candidate which parts are still unfinished, if any, and when it is worth coming
  back. `references/honest-context-interview.md` has the revisit triggers: after a
  rejection that stung, after an offer, when a dealbreaker gets tested for real.
- If a real metric came up, put it in `profile/resume.json` and say you did.
- If a language preference came up, put it in `profile/tone.md` and say you did.
- Suggest a git commit; do not make one.
